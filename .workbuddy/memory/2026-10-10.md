## AO 四 Pass 的数值缺陷修复（SSAO / HBAO / HBAO+ / GTAO）

延续 Forward+ 与四个 AO Pass 的收尾。上一轮遗留 `verify_ao.mjs` 44/46（GTAO 在箱根处 0.9101 超阈值）。
用临时探针（`tools/_probe_ao.mjs`，用完已删）逐项隔离后，定位出**三个真实缺陷**，其中前两个是根因级的：

### 1) 反投影必须用「像素中心 uv」（根因，影响 SSAO/HBAO/HBAO+/GTAO 全部）
- 旧代码：`sd = depthAtUV(suv)` 取最近像素的深度，却仍用**精确行进 uv** 做 `viewPosFromDepth(suv, sd)`。
- 深度值属于**像素中心那条视线**，用别的 uv 反投影得到的点根本不在几何体表面上，
  误差 = 像素偏移 × 深度梯度。掠射角下深度梯度极大 → 平坦地面被重建出巨大高度差 → 自遮挡发黑。
- 症状特征：结果**强烈依赖采样步数**。实测 `GTAO_STEPS` 8→12 时掠射地面从 0.964 崩到 0.752，
  开阔地面从 0.999 掉到 0.964。之前"能扛住掠射"纯属步数小的侥幸。
- 修法：新增 `snapUV()` + `sampleSurface()`（先吸附到像素中心，再用**吸附后**的 uv 反投影）。
- 效果：开阔与掠射地面全部变成**精确 1.0000**，且 8/12/16/24/32 步结果完全一致（漂移 0.0000）。

### 2) 衰减距离不能用 `length(delta.xy)`（根因）
- `q = length(S.xy − P.xy)/radius` 把**仰角方向的抬升**也算成了水平距离：紧贴墙壁的高墙（最近的遮挡体）
  因抬升大而被判成"离得远"，衰减到接近 0。箱根处最强的那个样本（仰角 78°）atten 仅 0.05。
- 更糟：它**随相机朝向变化**——同一场景转个相机遮挡量就变，属明显缺陷。
- 修法：改用旋转不变的 `q = length(S − P)/radius`（三维距离，与"半径球"语义一致）。
- 注意不要改成切平面内水平距离：那样会把**远处高处**的遮挡体（如 3 单位外的天花板）算成完全遮挡。

### 3) 地平线积分要按弧段增量累加，而非取单样本最大值
- 旧：`best = max(sin^w(elev) × atten)`，只用到某一个距离处的衰减，
  把"近处低仰角 + 远处高仰角"的连续遮挡压成一个值，系统性偏低。
- 新：行进中把"新露出来的那段弧"按它自己那处的衰减累加
  - HBAO `weightPow=1`：`a = Σ (sin h_i − sin h_prev) × atten_i`（∫cos α dα = sin α）
  - GTAO `weightPow=2`：`a = Σ (sin²h_i − sin²h_prev) × atten_i`（∫sin α cos α dα = ½sin²α）
  - 两者在 h→π/2 均归一化到 1。
- 其中 `hPrev` 起始为 0（仰角以切平面为基准），因此平面上的样本恒为 0，任何视角都不自遮挡。

### 箱根可见度终值（RADIUS=0.8，开阔处 ~1.0000）
| 方法 | 可见度 | 说明 |
|---|---|---|
| ssao | 0.7500 | 经典半球采样 |
| hbao | 0.7434 | sin 权重 |
| hbaoplus | 0.7460 | 双尺度 + 平方衰减 |
| gtao | 0.8899 | 单次散射 0.8123 → 多重散射后 0.8899 |

GTAO 明显更亮是**有意设计**，已在测试里显式断言锁死，避免日后被误判成 bug：
① 余弦加权（sin² 而非 sin），低仰角遮挡体贡献本就该小得多；
② Jimenez 多重散射补偿作用在**可见度**上（亮表面抬高、暗表面压低）。

### 测试套件增补
- `verify_ao.mjs` 新增 **5b 节「结果必须与采样步数无关」**——像素吸附 bug 最好用的照妖镜。
  同时把 `pixelOf` 从 `Math.round(uv*W-0.5)` 改成 `Math.floor(uv*W)`，与 WGSL `vec2<i32>(uv*dim)` 截断语义严格对齐。
- 第 6 节补两条：`gtao 单次散射箱根 ≤ 0.90`（与其余三者同口径可比）、`多重散射只抬高可见度`。
- `package.json` 补 `verify:layout` / `verify:ao`，并折进聚合 `verify`。

## 几何绕序修复：makePlane / makeSphere 绕序与顶点法线反向

用户报告「测试场景的地面法线方向反了」。新建 `tools/verify_winding.mjs` 客观检查（不依赖任何 API
正反面约定：对每个三角形算右手法则几何法线 `cross(v1−v0, v2−v0)`，与三顶点法线均值比方向）后定位：

| 生成器 | 三角形 | 绕序自洽 | 结论 |
|---|---|---|---|
| makeCube | 12 | 12/12 = 100% | 基准（几何法线朝外，与顶点法线同向） |
| makePlane | 2 | **0/2 = 0%** | 几何法线 −Y，顶点法线 +Y → 完全反向 |
| makeSphere | 352（退化 32） | **0/352 = 0%** | 几何法线朝内，顶点法线朝外 → 完全反向 |

**为什么只有地面暴露**：`makePlane` 用作不透明地面（pGeometry，`cullMode:"back"`），绕序反了就从上方
被**整片剔除**；`makeSphere` 只被透明玻璃球用（pTransparent，`cullMode:"none"`），剔除被关掉，
bug 一直被掩盖。

**修法**（修绕序，不翻顶点法线——翻法线会让地面从下方受光）：
- `makePlane`：`idx` 由 `[0,1,2, 0,2,3]` → `[0,2,1, 0,3,2]`
- `makeSphere`：`idx.push(a,c,b, b,c,d)` → `idx.push(a,b,c, b,d,c)`
- `makeCube` 不动（它是基准约定）

**副作用（需留意）**：地面此前在 `pShadow`（同为 `cullMode:"back"`）里也被剔除，修复后会**新进入
shadow map**。接收端的 `baseBias`（0.0006 起，CSM 逐级 +0.0009）本就是为自阴影设计的，立方体已在用
同一套，故未盲调阴影参数。

**沉淀**：`Scene.ts` 几何段顶部写死绕序约定（几何法线必须与顶点法线同侧；不一致的症状是「物体从外面
消失」而非「变黑」，极易误诊）；`package.json` 新增 `verify:winding` 并折进 `verify`。

终态：verify 全绿 —— wgsl 1/1 · pipelines 13/13 · layout 全部一致 · **winding 13/13** · lights 51/51 ·
ao 53/53；`npm run build` 成功（99.38 kB / gzip 29.60 kB）。

## CSM 修复：级联选择 off-by-one（主因）+ 混合带失效 + 半影放大 + texel 对齐口径

用户报告「CSM 渲染物体背面有错误」。对截图做了客观取证（同色连通域分割 + 面内高频分析）：
**四个可见面内 |Δ| 全在 0.11–0.8（背景自身 0.16–0.44）→ 完全没有 acne 散斑/条带**，
且左右两列纵向亮度剖面完全相同、无地平线硬边 → 地面未渲染（应为上一轮绕序修复前的截图）。
排除 acne 后转向代码，定位出同一段 CSM 里的**四个相关缺陷**，全部可复现：

### ① 级联选择 off-by-one（主因，症状是「静默无阴影」）
- `shadowCascade()` 写成 `if (viewDepth > csmSplits[c]) cascade = c;`
- 但 `csmSplits[c] = bounds[c].f` 是级联 c 的**远界**（`Lighting.wgsl:21` 的注释、`bounds[c] = [splits[c-1], splits[c]]`、
  `splitCascadeDistances` 的 doc 三处一致）。选择逻辑把远界当成了近界。
- 后果：`viewDepth > splits[0]`(=8.70) 起，选中的级联恒小一级，其正交框不含该点 →
  `projectToUV` 出界 → 直接 `return 1.0`（判为受光）。级联 3 只在 v>100（=相机远平面）被选中 → **从不被采样**。
- 量化：demo 相机下 13001 个视深度采样点中 **12168 个**落在所选级联框外。近平面到 near*4 之间的
  v 不属于任何级联，不参与判定。
- 修法：`cascade = c + 1` 后 `min(cascade, count - 1)`（=「第一个 v ≤ splits[c] 的 c」）。

### ② 混合带位置错误 → 融合永不触发
- 旧：`bandStart = mix(csmSplits[cascade], csmSplits[cascade+1], 0.75)` —— bandStart 落在**下一级联**区间里，
  于是 `viewDepth < bandStart` 恒成立，直接 return s1，级联边界留硬接缝。
- 新：band 取本级联**最后 25%**：`bandEnd = csmSplits[cascade]`，`bandPrev = (cascade>0 ? csmSplits[cascade-1] : 0)`，
  `bandStart = mix(bandPrev, bandEnd, 0.75)`，`smoothstep(bandStart, bandEnd, v)`。

### ③ linearizeDepth 用共享 zFar → 近处级联半影被放大近一个数量级
- 着色器只能拿到一组 near/far，代码给了最远级联的 `base.r*6+10`；但各级联 actual far = `r_c*6+10`。
- `penumbraUV = (dRecv - dBlk) * tanθ/(2r_c)`，其中 d 由 ndc × (zFar−zNear) 得来，于是被放大
  `(zFarBase-zNear)/(zFarC-zNear)` 倍 —— demo 下**级联 0 放大 9.31×**，顶到 `penumbraUV ≤ 0.12` 上限，
  近处阴影被糊没。
- 修法：把比例 k 折进已按级联存的 `lightSizeUV`（= `csmSizes[c]`），**无需改 Light 结构体**：
  `ld[o+24+c] = tanθ/(2r_c) * (zFarC - zNear)/(zFarBase - zNear)`。

### ④ texel 对齐用最远级联的 texel
- 旧：所有级联都传 `texel = base.r*2/CSM_RES`（最远级联的粗 texel）。
  既对不齐近处级联自己的细网格（抖动消不掉），又把近处包围球中心最多推开半个粗 texel ——
  相对近处很小的半径，偏移可达半径 1%+，足以把切片边缘挤出正交框。
- 新：`texel_c = (r_c*2)/CSM_RES`，逐级联各用各的。

### 重构与测试沉淀
- `Math.ts` 新增并导出 `cascadeBounds()`（splits/bounds 约定 + 注释钉死）、`selectCascade()`（WGSL 的参考实现）、
  `cascadeMatrix()`（从 Renderer 的私有方法提出来，便于测试测真代码）。
- 新增 `tools/verify_csm.mjs`（49 项）：约定自洽 / 每级联中点与端点选中自己 + 无死级联 /
  级联矩阵把**自己的视锥切片 8 角点**映射进单位立方体（4 种 aspect）/ 混合带在本级联区间内且可达 /
  **CPU↔GPU 选择逻辑对拍**（字面复刻 WGSL 循环，13001 点全域一致）+ 旧写法反证 /
  半影 k 补偿等价性 / **源码守卫**（两个 WGSL 必须含 `cascade = c + 1`、`bandEnd`，且不得回退旧写法）。
- `package.json` 新增 `verify:csm` 并折进 `verify`。

★ 教训：这类 bug 的可怕之处是**静默**——出界时 `return 1.0` 让阴影不报错、不闪烁，只是「没了」。
所以凡「采样越界兜底为安全值」的分支，都必须配一条覆盖性测试。

终态：verify 全绿 —— wgsl 1/1 · pipelines 13/13 · layout 一致 · winding 13/13 ·
**csm 49/49** · lights 51/51 · ao 53/53；build 成功（100.37 kB / gzip 30.51 kB）。

## 渲染路径从 2 条扩到 4 条：Traditional Forward + Tiled Deferred

用户要求「加上传统的 Forward Rendering 管线，Tiled Based Deferred Rendering」。现在四条路径构成一张
「光照位置 × 光源裁剪」的对照表：

| 路径 | G-buffer / 前置 | 光源裁剪 | 光照位置 | 额外输出 |
|---|---|---|---|---|
| `forward`（传统 Forward） | 无 | 无 | 逐物体片元着色器（**全部**光源） | HDR + **velocity** |
| `forward+` | 前置（深度+法线+albedo+velocity，**不写世界坐标**） | 分块 | 逐物体片元着色器（分块列表） | — |
| `deferred` | 全量 G-buffer | 无 | 全屏光照（全部光源） | — |
| `tiled-deferred` | 全量 G-buffer | 分块 | 全屏光照（分块列表） | — |

### 关键设计：两个入口点共用一份光照代码
- `Lighting.wgsl`：抽出 `shadeLight()`（单灯贡献）+ `shadePixel(frag, tiled : bool)`，
  `fs` = 遍历 `frame.params.x` 个光源，`fs_tiled` = 遍历 `lightGrid[tile]` / `lightIndices`。
- `ForwardPlus.wgsl`：同样抽出 `shadeLight()` + `shadePixel(px, worldPos, normal, tiled)`；
  `fs` = 分块列表，`fs_forward` = 全部光源。传统 Forward 另加 `vs_forward`/`VSOutV`，
  多带 velCurr/velPrev 并输出 `@location(1) velocity` —— 它没有前置通道，TAA 的运动矢量只能自己写。
- WGSL 的 `continue` 不能跨函数，剔除分支改写为 `return vec3(0.0)`。
- **不复制 BRDF / 阴影代码**：否则改一条路径漏另一条，四条路径画质会慢慢漂移。
  `verify_layout.py` 新增守卫：两个入口点的函数体里必须出现 `shadePixel(`。

### ★ 踩到的坑：共享体 + 运行时分支 ⇒ 布局不能更小
`fs` 与 `fs_tiled` 共用 `shadePixel`，其中 `if (tiled) { lightGrid[...] }` 是运行时分支，
所以 `lightGrid`/`lightIndices` **从 `fs` 也静态可达**。给 `fs` 用只含 2 个 buffer 的旧 `lightBGL`
布局，管线创建被 Dawn 直接拒绝：
`Shader global ResourceBinding { group: 3, binding: 2 } is not available in the pipeline layout`。
⇒ 两条延迟光照管线**必须共用**含 4 buffer 的 `lightPlusBGL` 布局（Deferred 那一路运行时永不读分块缓冲，代价为 0）。
这个错误 tsc 与 WGSL 编译都发现不了，只有真正 createRenderPipeline 才暴露——
`validate_pipelines.py` 的价值正在于此。

### 补的一个既有缺陷：前向路径没有天空
天空渐变原先**只**写在 `Lighting.wgsl` 的 `fs` 里（`depth >= 1` 处返回）。延迟路径的全屏着色器覆盖每个像素，
所以顺手就有了；而 Forward+ / 传统 Forward 只对几何体覆盖的像素执行片元着色器，**背景像素永远执行不到**，
背景就是清屏色（黑）。加了新路径后这个不一致会很刺眼。
⇒ 新增 `Sky.wgsl`（全屏渐变）+ `pSky`（布局只含 Frame），**仅前向路径**在几何之前铺一趟天空，
几何通道的 hdrScene 由 `clear` 改为 `load`。延迟路径保持原样（不需要多这一趟）。
⇒ 两处渐变公式必须同色，`verify_layout.py` 新增正则比对守卫生效。

### 通道编排（Renderer.render）
编号统一为：1 阴影 → 2a 前置 / 2b G-buffer /（传统 Forward 无几何通道）→ 3 AO → 4 分块剔除 →
5 天空（仅前向）→ 6a/6b/6c 着色 → 7 透明 → 8 TAA → 9 Bloom → 10 合成。
- 传统 Forward 的 **AO 强制走 `fs_off`**：没有 G-buffer 就没有深度/法线可读；这一趟同时充当 aoTex 的清零。
  HUD 显式显示「AO: 不可用（Forward 无 G-buffer）」，不让开关静默失效。
- 新增 `pathHasGBuffer()` / `pathIsTiled()` / `pathIsForward()` 三个纯函数概括路径语义，
  编排里不再散落字符串比较。
- `RENDER_PATHS = ["forward", "forward+", "deferred", "tiled-deferred"]`，`get lightCount()` 供 HUD。

  build 109.01 kB / gzip 33.93 kB。
